# 四则运算题目生成程序——需求分析

## 1. 项目概述

本项目使用 **Java + Maven** 开发一个命令行四则运算题目生成程序。

程序能够按照用户指定的题目数量和数值范围，自动生成符合要求的小学四则运算题目，并将题目保存到文件中。

程序还支持对已有的题目文件和答案文件进行自动判题，并统计正确、错误的题目数量。

## 2. 运行环境

- 开发语言：Java
- 项目管理工具：Maven
- 程序运行方式：命令行
- 输出文件：UTF-8 文本文件
- 支持的主要操作系统：Windows / Linux / macOS

## 3. 功能需求

### 3.1 四则运算题目生成

程序支持通过命令行参数生成指定数量的四则运算题目。

生成命令：

```powershell
java -jar Arithmetic.jar -n 10 -r 10
```

其中

- `-n`：指定生成的题目数量。
- `-r`：指定题目中自然数、真分数以及真分数分母的取值范围。
- `-r` 参数必须提供。
- `-n` 未提供时使用程序规定的默认值或给出参数错误提示。

生成的题目保存到当前执行目录下：

```
Exercises.txt
```

文件格式：

```
1. 题目1
2. 题目2
3. 题目3
...
```

### 3.2 表达式要求

程序生成的表达式应符合题目规定的四则运算语法：

```tex
e = n
  | e1 + e2
  | e1 - e2
  | e1 × e2
  | e1 ÷ e2
  | (e)
```

其中操作数可以是：

- 自然数：`0, 1, 2, ...`
- 真分数：`1/2`
- 带分数：`1'1/2`

输出时：

```tex
3/5
2'3/8
```

分别表示三分之五和二又八分之三。

### 3.3 运算合法性

生成的题目必须满足以下条件：

1. 表达式中的运算符数量不超过 **3 个**。
2. 减法运算不能产生负数，即：

```java
e1 - e2 >= 0
```

1. 除法运算的结果必须是真分数。
2. 分数运算应按照实际数学规则计算，并进行必要的约分。
3. 表达式的计算结果必须能够正确表示和输出。

例如：

```tex
1/6 + 1/8 = 7/24
```

### 3.4 重复题检测

同一次运行生成的题目不能重复。

对于加法和乘法，应考虑交换律，例如：

```tex
23 + 45
45 + 23
```

属于同一道题。

```tex
6 × 8
8 × 6
```

也属于同一道题。

同时需要按照题目规定处理结合关系，例如：

```tex
3 + (2 + 1)
1 + 2 + 3
```

属于重复题目，而：

```tex
1 + 2 + 3
3 + 2 + 1
```

不属于重复题目。

因此程序需要对表达式进行适当的**规范化处理**，再进行重复性判断。

### 3.5 题目数量

程序应支持至少生成：

```tex
10000
```

道题目。

当生成大量题目时，应保证：

- 不生成重复题目；
- 不违反表达式约束；
- 程序能够正常结束；
- 生成结果能够正确写入文件。

### 3.6 参数错误处理

当用户输入的命令行参数不符合要求时，程序应给出明确的错误提示。

例如：

```tex
缺少 -r 参数
-r 参数必须为正整数
-n 参数格式错误
参数组合不合法
```

必要时输出程序使用帮助信息。

## 4. 判题功能

程序支持根据已有的题目文件和答案文件进行自动判题。

命令格式：

```powershell
java -jar Arithmetic.jar -e <exercisefile>.txt -a <answerfile>.txt
```

其中：

- `-e`：指定题目文件。
- `-a`：指定答案文件。

程序读取题目和答案，逐题进行计算和比较。

判题结果保存到：

```tex
Grade.txt
```

格式：

```tex
Correct: 5 (1, 3, 5, 7, 9)
Wrong: 5 (2, 4, 6, 8, 10)
```

其中：

- `Correct` 表示答案正确的题目；
- `Wrong` 表示答案错误的题目；
- 前面的数字表示对应题目的数量；
- 括号中的数字表示题目编号。

## 5. 非功能需求

### 5.1 正确性

程序生成的所有题目必须符合题目规定的语法和运算约束，计算结果必须正确。

### 5.2 性能

程序应能够在合理时间内完成 10000 道题目的生成，并能够处理相应规模的文件。

### 5.3 可维护性

程序采用模块化设计，将命令行处理、表达式生成、表达式计算、重复题判断、文件读写和判题等功能进行合理划分。

### 5.4 可测试性

核心功能应能够进行独立测试，并至少设计 10 个测试用例验证程序正确性。

## 6. 输入与输出

| 功能     | 输入       | 输出              |
| -------- | ---------- | ----------------- |
| 生成题目 | `-n`、`-r` | `Exercises.txt`   |
| 参数检查 | 命令行参数 | 错误信息/帮助信息 |
| 自动判题 | `-e`、`-a` | `Grade.txt`       |

## 7. 项目约束

本项目采用：

- **Java** 作为开发语言；
- **Maven** 进行项目构建和依赖管理；
- **CLI** 作为主要交互方式；
- 使用 Git 进行源代码版本管理；
- 使用 JUnit 进行单元测试。

本阶段只确定系统的功能和约束，不规定具体的算法实现。表达式树、分数类、题目生成算法、重复题规范化算法等具体设计将在后续设计文档中确定。
