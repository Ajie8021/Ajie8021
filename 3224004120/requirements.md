论文查重项目需求分析

##### 1. 项目概述

###### 1.1 项目名称

论文查重

###### 1.2 项目目标

本项目旨在实现一个论文文本重复率计算程序。程序接收原始论文文件和疑似抄袭论文文件，经过文本读取、预处理和相似度计算后，将计算得到的重复率按照规定格式写入指定的答案文件。

###### 1.3 项目背景

本项目用于实践软件工程项目的完整开发流程，包括需求分析、系统设计、编码实现、单元测试、代码复审、性能分析与优化以及项目总结等环节。

##### 2. 功能需求

###### 2.1 文件输入

程序通过命令行参数接收三个文件路径：

```
java -jar main.jar [original file] [plagiarism file] [answer file]
```

其中：

- `original file`：原始论文文件；
- `plagiarism file`：疑似抄袭论文文件；
- `answer file`：程序计算结果的输出文件。

###### 2.2 文本读取

程序应能够根据输入的文件路径读取原始论文和疑似抄袭论文的内容。

程序应正确处理正常的文本文件，并对文件不存在、无法读取等异常情况进行处理。

###### 2.3 文本预处理

输入样例文件中包含 HTML 页面相关内容，因此程序在进行重复率计算前，需要从输入内容中提取实际需要进行比较的论文文本。

文本预处理主要包括：

1. 去除不参与论文内容比较的 HTML 标签及页面结构信息；
2. 提取有效文本内容；
3. 对 HTML 特殊字符或实体进行必要处理；
4. 对无意义的空白字符进行规范化；
5. 得到用于相似度计算的文本序列。

> 注：具体的 HTML 解析和文本规范化方案在系统设计阶段进一步确定。

###### 2.4 重复率计算

程序需要根据原始论文和疑似抄袭论文的有效文本计算重复率。

根据对测试样例的分析，会发现测试数据包含字符增加、字符删除以及不同程度的字符顺序调整等情况，因此初步考虑采用基于字符序列的相似度计算方法，即最长公共子序列（`LCS`）算法。

初步计算模型为：

```
重复率 = 两篇文本的最长公共子序列长度 / 原始论文有效文本长度
```

该计算方式目前作为算法设计阶段的候选方案，最终计算公式需要结合全部测试样例及题目规定进一步验证。

###### 2.5 结果输出

程序将计算得到的重复率写入指定的答案文件。

输出结果应为浮点数，并保留两位小数。

例如：

```
0.80
```

##### 3. 测试样例分析

根据目前提供的测试样例，可以观察到测试数据包含多种文本修改方式。

| 样例类型 | 目前观察到的特点             | 对程序的要求                     |
| -------- | ---------------------------- | -------------------------------- |
| `add`    | 在原始文本基础上增加部分字符 | 应能够识别仍然保留的原始文本     |
| `del`    | 删除原始文本中的部分字符     | 应能够处理文本长度减少的情况     |
| `dis_1`  | 字符顺序发生一定程度调整     | 应能够处理字符顺序变化           |
| `dis_10` | 字符发生较明显的重新排列     | 应能够处理较大程度的字符顺序变化 |
| `dis_15` | 字符顺序发生更加明显的扰动   | 应能够处理严重字符重排           |

从目前对 `dis_10` 和 `dis_15` 样例的观察可以发现，部分文本并非简单地增加或删除字符，还对原有字符进行了较明显的重新排列。因此，算法设计不能仅仅考虑连续字符串匹配。

##### 4. 非功能需求

###### 4.1 性能要求

程序应满足题目规定的运行时间和资源限制：

- 单个测试点运行时间不超过 5 秒；
- 内存使用不超过 2048 MB；
- 不得出现严重的内存泄漏；
- 不得出现影响程序正常运行的严重异常。

由于论文文本长度可能较大，相似度算法的时间复杂度和空间复杂度需要重点考虑。

###### 4.2 可维护性

程序应具有清晰的模块划分和合理的代码结构。

不同功能应尽可能分离，例如：

```
文件读取
    ↓
文本预处理
    ↓
相似度计算
    ↓
结果格式化
    ↓
文件输出
```

核心计算模块应具有明确的接口，便于后续测试和算法优化。

###### 4.3 可测试性

程序需要进行单元测试。

要求：

- 至少编写 10 个测试用例；
- 对主要功能和异常情况进行测试；
- 使用测试覆盖率工具检查代码覆盖情况；
- 重点关注分支覆盖率；
- 测试过程中发现的问题应及时修改并重新测试。

###### 4.4 代码质量

程序应符合项目制定的代码规范，并通过题目要求的代码质量分析。

需要尽可能消除：

- 编译警告；
- 无效代码；
- 不合理的命名；
- 重复代码；
- 不必要的复杂逻辑；
- 未处理的异常。

###### 4.5 性能优化

程序完成初版实现后，需要使用 Profiling Tools 对程序运行情况进行分析，定位主要性能瓶颈，并针对瓶颈进行优化。

优化前后应进行测试和性能对比，以验证优化效果。

##### 5. 异常处理需求

程序应对可能出现的异常情况进行合理处理，包括但不限于：

###### 5.1 命令行参数错误

当命令行参数数量不足或格式不正确时，程序应给出明确的错误提示，而不是直接产生未处理异常。

###### 5.2 输入文件不存在

当原始论文文件或疑似抄袭论文文件不存在时，应进行异常处理并给出相应提示。

###### 5.3 文件无法读取

当文件存在但由于权限、编码或其他原因无法正常读取时，应进行处理。

###### 5.4 输出文件无法写入

当指定的答案文件无法创建或写入时，应进行异常处理。

###### 5.5 空文件

程序需要考虑原始论文或疑似抄袭论文为空的情况，并避免出现除零等运行时异常。

空文本情况下的具体结果规则需要在算法设计阶段明确。

##### 6. 输入约束

程序输入主要为两个论文文件和一个输出文件路径。

输入文件可能包含：

- 中文文本；
- 英文文本；
- 中英文混合文本；
- 标点符号；
- 换行和空白字符；
- HTML 标签及相关页面内容。

程序不应依赖固定的文件名，必须使用命令行提供的文件路径。

##### 7. 输出约束

程序必须将结果写入第三个命令行参数指定的文件。

输出结果：

- 为浮点数；
- 保留两位小数；
- 不应输出无关的调试信息到答案文件。

##### 8. 安全与运行环境要求

根据题目要求：

- 程序不得访问与任务无关的文件；
- 程序运行过程中不得进行网络访问；
- 程序不得依赖外部网络服务完成重复率计算；
- 程序应在规定的内存和时间限制内完成计算。

##### 11. 需求分析结论

本项目的核心功能可以概括为：

```
命令行参数
    ↓
读取原始论文
    ↓
读取疑似抄袭论文
    ↓
提取并规范化有效文本
    ↓
计算文本相似度
    ↓
格式化重复率
    ↓
写入答案文件
```

在当前阶段，字符级 `LCS` 可以作为重复率计算的主要候选算法，但在获得全部测试样例及标准结果并进行验证之前，不将其确定为最终算法。
